## 1. 제품 개요

깨남.COM는 리그 오브 레전드 플레이어가 탑, 정글, 미드, 원딜, 서폿 중 자신의 포지션을 고른 뒤 상대할 챔피언을 빠르게 선택하고, 보편적으로 적용되는 `공통` 상대법과 자신의 챔피언에만 적용되는 `Me` 상대법을 함께 확인하는 웹사이트다.

상대법은 **매치업마다 하나의 위키 문서**로 모인다. 같은 지식이 여러 글에 흩어져 좋아요 수로 경쟁하는 대신, 한 문서를 여러 사람이 고쳐 나간다. 틀린 내용은 다음 사람이 바로잡는다.

첫 화면에서는 포지션 선택 메뉴와 포지션별 카테고리 포스터를 보여 준다. 사용자가 카테고리를 선택하면 해당 포지션과 카테고리에 속한 챔피언 아이콘만 표시하며, 챔피언을 선택하면 짧은 CSS 애니메이션과 함께 해당 포지션의 챔피언 상대법 페이지로 이동한다. 상대법 페이지는 챔피언 정보 Aside와 상대법·영상 탭이 있는 Main으로 구성한다.

### 1.1 주요 용어

| 용어 | 의미 |
| --- | --- |
| 문서 | 상대 챔피언 하나에 대응하는 위키 문서. **챔피언당 정확히 하나**이고, 포지션은 문서의 식별자가 아니라 분류다 (2026-09-04 개정) |
| 섹션 | 문서를 이루는 편집 단위. `공통` 섹션 하나와 내 챔피언별 `Me` 섹션들로 이루어진다 |
| `공통` | 사용자의 챔피언과 관계없이 항상 표시되는 상대법 섹션 (구 `General`) |
| `Me` | 특정 내 챔피언을 선택했을 때만 함께 표시되는 전용 상대법 섹션 |
| 편집 제안 | 섹션 하나를 고쳐 제출한 것. 지운 것이 없으면 즉시 반영되고, 지우거나 고쳤으면 검토를 거친다 |
| 리비전 | 문서에 반영된 편집의 일련번호. 승인된 편집 제안이 곧 리비전이 된다 |
| 검토 | 운영자가 대기 중인 편집 제안을 승인·거절하는 행위 |
| 편집 정책 | 문서별로 편집을 얼마나 여는지 나타내는 `guarded`, `open`, `locked` 상태 |
| 포지션 | 탑, 정글, 미드, 원딜, 서폿 중 상대 챔피언이 플레이되는 역할 |
| 카테고리 | 포지션 안에서 챔피언을 다시 나누는 깨남.COM의 운영 분류 |
| 챔피언 운영 상태 | 챔피언 전체를 공개 기능에서 사용할지 나타내는 `활성` 또는 `비활성` 상태 |
| 분류 검토 상태 | 동기화된 챔피언의 운영 검토 여부를 나타내는 `검토 대기` 또는 `검토 완료` 상태 |
| 데이터 소스 상태 | 지정 Data Dragon 카탈로그에서의 존재 여부를 나타내는 `정상` 또는 `소스 누락 검토 필요` 상태 |
| 분류 노출 상태 | 특정 챔피언·포지션 분류를 공개 목록에 표시할지 나타내는 `노출` 또는 `숨김` 상태 |
| 분류 보관 | 현재 배정에서 논리적으로 제거하되 이력과 참조를 위해 레코드를 물리 삭제하지 않고 보존하는 상태 |
| 미분류 | 보관되지 않은 현재 포지션·카테고리 분류가 하나도 없는 파생 상태 |
| Aside / Main | 챔피언 정보 영역 / 상대법 문서와 영상 콘텐츠 영역을 뜻하는 화면 레이아웃 용어 |
| 운영자 선별 영상 | `영상` 탭에 표시하는 운영자 등록·검수 콘텐츠 |
| 문서 첨부 영상 | 문서에 추가해 그 문서에서만 표시하는 외부 영상. v0.7에서 용어만 정의되고 요구사항이 없었으며, 현재 데이터 모델에도 없다. 도입 시점은 미정 |

## 2. 배경 및 문제 정의

상대법은 포지션, 챔피언 조합, 스킬 교환 방식, 성장 구간 등에 따라 달라진다. 그러나 관련 정보가 영상, 커뮤니티 글, 개인 메모 등에 흩어져 있어 필요한 내용을 빠르게 찾기 어렵고, 검색 결과만으로는 어느 포지션과 챔피언 관점의 공략인지 파악하기도 어렵다.

깨남.COM는 다음 문제를 해결한다.

- 사용자가 현재 상대해야 할 챔피언의 공략 페이지를 시각적으로 빠르게 찾기 어렵다.
- 특정 상대 챔피언에 대한 실전 팁이 여러 채널에 분산되어 있다.
- 기존 공략은 길거나 범용적이어서 게임 직전에 핵심만 확인하기 어렵다.
- 사용자 경험에서 나온 최신 상대법을 한곳에 축적하기 어렵다.

## 3. 목표

### 3.1 제품 목표

1. 사용자가 첫 화면 진입 후 4번 이내의 상호작용으로 원하는 상대법 문서에 도달하게 한다.
2. 포지션, 카테고리와 챔피언 이미지를 차례로 탐색하게 하여 전체 목록보다 빠르고 직관적인 선택 경험을 제공한다.
3. `공통`과 `Me`를 구분해 범용 상대법과 챔피언 특화 상대법이 섞이는 문제를 해결한다.
4. 챔피언의 스킬 정보, 상대법 문서, 관련 영상을 한 페이지에서 탐색하게 한다.
5. 모바일과 데스크톱 모두에서 동일한 핵심 흐름을 제공한다.
6. 운영자가 배포 없이 챔피언의 포지션·카테고리 분류를 안전하게 갱신할 수 있게 한다.
7. 흩어진 상대법을 매치업당 하나의 문서로 모으고, 여러 사람이 이어서 고칠 수 있게 한다.
8. 문서가 비어 있는 초기에도 첫 기여가 즉시 드러나 기여자가 결과를 확인할 수 있게 한다.

### 3.2 비목표

MVP에서는 다음 기능을 제공하지 않는다.

- 전체 게임 전적 검색 및 분석 기능. MVP에서는 `전적` 메뉴와 추후 개발 안내 화면만 제공한다.
- 실시간 게임 데이터나 승률 통계 기능. MVP에서는 `통계` 메뉴와 추후 개발 안내 화면만 제공한다.
- 티어표 자동 생성 기능. MVP에서는 `티어표` 메뉴와 추후 개발 안내 화면만 제공한다.
- 사용자의 직접 영상 업로드 및 라이브 스트리밍
- 실시간 채팅 및 개인 메시지
- 경기 통계나 메타 데이터를 이용한 챔피언 포지션·카테고리 자동 분류 및 자동 게시
- 포지션과 카테고리 기준 자체를 관리자 화면에서 생성·수정·삭제하는 기능
- 챔피언 분류의 CSV 가져오기·내보내기, 예약 동기화와 자동 공개
- 챔피언 분류의 다단계 검토·승인 워크플로

## 4. 대상 사용자

### 핵심 사용자

- 특정 포지션을 처음 배우며 챔피언별 기본 상대법이 필요한 사용자
- 주력 챔피언의 불리한 매치업 팁을 게임 전에 빠르게 확인하려는 사용자
- 자신이 익힌 라인전, 정글 동선과 교전 지식을 다른 플레이어에게 공유하려는 사용자

### 운영 사용자

- 패치와 메타 변화에 맞춰 챔피언의 포지션·카테고리 분류를 관리하는 깨남.COM 관리자

### 주요 사용 상황

- 게임 시작 전 상대 챔피언을 확인하고 핵심 대응법을 찾는다.
- 자신의 챔피언으로 여러 상대 챔피언을 만났을 때의 공략을 탐색한다.
- 게임이 끝난 뒤 유용했던 스킬 교환법, 정글 동선이나 주의점을 문서에 보탠다.
- 관리자가 신규·역할 변경 챔피언을 찾아 분류하고 공개 여부와 표시 순서를 조정한다.

## 5. MVP 범위

### 5.1 포지션·챔피언 선택 화면

- 첫 화면 상단에 `탑`, `정글`, `미드`, `원딜`, `서폿` 포지션 선택 메뉴를 이 순서로 표시한다.
- URL에 포지션이 없으면 `미드`를 기본 선택하고, 포지션 선택 상태를 URL에 반영해 새로고침과 뒤로 가기 후에도 복원한다.
- 선택한 포지션 아래에는 다음 카테고리를 대표 이미지와 함께 비대칭 포스터 형태로 표시한다.

| 포지션 | 카테고리 | 대표 이미지 | 역할 |
| --- | --- | --- | --- |
| 탑 | 탱커 | `/images/Mundo.jpg` | 탱커형 탑 챔피언의 진입점 |
| 탑 | 딜탱 | `/images/Aatrox.jpg` | 전사·브루저형 탑 챔피언의 진입점 |
| 탑 | 딜러 | `/images/Teemo.jpg` | 공격형 탑 챔피언의 진입점 |
| 정글 | AD | `/images/Leesin.jpg` | 물리 피해 중심 정글 챔피언의 진입점 |
| 정글 | AP | `/images/Lillia.jpg` | 마법 피해 중심 정글 챔피언의 진입점 |
| 미드 | 암살자 | `/images/Zed.jpg` | 암살자형 미드 챔피언의 진입점 |
| 미드 | 메이지 | `/images/Zoe.jpg` | 마법사형 미드 챔피언의 진입점 |
| 미드 | 브루저/원딜 | `/images/Yone.jpg` | 전사형 및 원거리 딜러형 미드 챔피언의 진입점 |
| 원딜 | 원딜 | `/images/Caitlyn.jpg` | 원딜 챔피언 전체의 단일 진입점 |
| 서폿 | Mom | `/images/Lulu.jpg` | Mom 유형 서폿 챔피언의 진입점 |
| 서폿 | Dad | `/images/Blitz.jpg` | Dad 유형 서폿 챔피언의 진입점 |
| 서폿 | Wtf?! | `/images/Brand.jpg` | Wtf?! 유형 서폿 챔피언의 진입점 |

- 각 카테고리 포스터에는 대표 이미지와 카테고리명을 함께 표시한다.
- 데스크톱에서 포스터가 2개 이상인 그룹의 특정 카테고리 포스터에 마우스를 올리거나 키보드 포커스를 두면 해당 포스터가 좌우로 확장되고 나머지 포스터는 좁아지는 짧은 애니메이션을 제공한다. 포인터나 포커스가 벗어나면 원래 배치로 복원하고, 시각적으로 일부가 잘리더라도 카테고리명과 선택 영역은 유지한다. 포스터가 하나인 원딜은 폭을 바꾸지 않고 기울기·하드 그림자 등의 선택 피드백만 제공한다.
- 터치 환경에서는 포인터 호버를 전제로 하지 않고 탭에 대한 선택 피드백을 제공하며, 애니메이션 감소 설정에서는 포스터 크기 변화를 제거하거나 최소화한다.
- 포지션을 바꾸면 이전 카테고리, 검색어와 챔피언 목록을 초기화하고 새 포지션의 카테고리 포스터를 표시한다.
- 카테고리를 선택하면 해당 포지션과 카테고리에 속한 챔피언 아이콘만 그리드로 표시한다.
- 챔피언 아이콘에 이름을 겹쳐 표시하지 않는다. 다만 이름을 보조 기술이 읽을 수 있어야 하고, 이름 검색으로 목록을 좁힐 수 있어야 한다.
- 사용자가 현재 선택한 포지션과 카테고리를 모두 명확히 알 수 있어야 하며, 다른 포지션이나 카테고리로 바로 전환할 수 있어야 한다.
- 상대 챔피언 이름 검색은 선택된 포지션과 카테고리 안의 챔피언만 대상으로 한다.
- 검색어를 지우면 선택한 포지션·카테고리의 전체 챔피언 아이콘을 다시 표시한다.
- 화면 크기에 따라 카테고리 포스터와 챔피언 아이콘 그리드의 열 수가 자연스럽게 변경되어야 한다. 챔피언 Contact Sheet는 데스크톱 12~13열, 태블릿 8열, 모바일 4열을 기준으로 하며, 데스크톱 아이콘은 약 84~96px 범위에서만 커져 목록이 적을 때 대형 카드로 늘어나지 않아야 한다.
- 포지션, 카테고리 및 챔피언 목록은 화면 코드에 개별적으로 고정하지 않고 데이터 기반으로 관리한다.

### 5.2 카드 및 아이콘 클릭 애니메이션

- 포지션 메뉴, 카테고리 포스터 또는 챔피언 아이콘을 클릭하거나 키보드로 선택하면 선택 상태를 알 수 있는 짧은 CSS 애니메이션을 실행한다.
- 애니메이션은 확대, 테두리 강조 또는 오버레이 등으로 명확한 피드백을 제공한다.
- 카테고리 선택 애니메이션 후 해당 카테고리의 챔피언 아이콘 목록을 표시한다.
- 챔피언 선택 애니메이션 후 해당 상대 챔피언의 상대법 페이지로 이동한다.
- 중복 클릭으로 화면 이동이 여러 번 실행되지 않아야 한다.
- `prefers-reduced-motion`이 활성화된 환경에서는 움직임을 제거하거나 최소화한다.

### 5.3 챔피언 상대법 페이지

사용자가 미드에서 아리 아이콘을 선택했다면 이 페이지에서 다루는 상대 포지션은 미드이고 상대 챔피언은 아리다. 페이지는 챔피언 정보를 보여 주는 `Aside`와 실제 콘텐츠를 보여 주는 `Main`으로 구성한다.

#### 5.3.1 Aside: 챔피언 정보

- `design/blueprints/ahri-matchup-v1.png`의 구도처럼 선택한 챔피언의 권리 확인된 정적 2D 일러스트를 Aside의 핵심 비주얼로 표시한다.
- 모든 챔피언 상대법 페이지는 정적 2D 일러스트로 통일하며 3D 모델, WebGL, 자동 회전, 드래그 회전 기능은 사용하지 않는다.
- 데스크톱과 모바일에서 핵심 피사체가 과도하게 잘리지 않도록 챔피언별 초점 위치를 지정하고, 일러스트 경로·대체 텍스트·사용 권한 확인 상태를 함께 관리한다.
- 이미지 영역의 크기와 종횡비를 미리 확보해 로딩 중 레이아웃 이동을 방지하고, 로드에 실패하면 챔피언 아이콘과 이름을 사용하는 대체 UI를 표시한다.
- 일러스트 로딩 실패가 상대법 문서와 스킬 정보의 표시를 막아서는 안 된다.
- 선택한 챔피언명(예: `아리`)을 크고 키치한 디스플레이 글꼴로 표시한다. 이름은 이미지가 아닌 실제 텍스트로 제공한다.
- 챔피언의 Q, W, E, R 스킬 아이콘 네 개를 1:1 비율로 표시한다. 패시브 스킬은 MVP 범위에서 제외한다.
- 스킬 아이콘에 마우스를 올리면 스킬명, 재사용 대기시간, 소모값, 범위, 상세 설명을 툴팁 또는 팝오버로 표시한다.
- 동일한 상세 설명을 키보드 포커스와 모바일 탭으로도 열고 닫을 수 있어야 한다.
- 스킬 아이콘과 설명은 패치 버전이 명시된 Riot Data Dragon 데이터를 기준으로 한다.

#### 5.3.2 Main: 상대법·영상 메뉴

- Main 상단에 `상대법`과 `영상` 메뉴를 탭 형태로 제공한다.
- 페이지 최초 진입 시 `상대법`을 기본 활성 메뉴로 표시한다.
- 사용자가 탭을 전환해도 현재 포지션과 상대 챔피언은 유지한다.
- 브라우저 새로고침과 뒤로 가기 후에도 선택한 탭을 복원할 수 있도록 URL에 탭 상태를 반영한다.
- `영상` 탭에 '롤깨남' 유튜브 채널의 상대법 영상을 Embed하여 추가할 예정.

#### 5.3.3 문서 열람과 Me 필터

- 문서는 현재 페이지의 포지션에서 해당 상대 챔피언을 상대하는 방법을 다룬다. 매치업당 문서는 하나다.
- 문서는 `공통` 섹션과 내 챔피언별 `Me` 섹션들로 이루어진다. 목록도 정렬도 없다.
- 문서 상단에 `Me`라는 레이블과 `내 챔피언 선택` 검색형 Combobox를 제공하며, 선택한 포지션에서 활성화된 챔피언을 기본 검색 대상으로 한다.
- 문서는 `공통` 섹션과 내용이 있는 모든 `Me` 섹션을 **한 번에** 표시한다. 목차가 하나이고 번호가 문서 전체를 관통한다.
- 사용자가 Combobox에서 자신의 챔피언을 선택하면 표시 범위를 좁히는 것이 아니라 그 섹션의 제목으로 이동한다.
- 선택한 챔피언의 `Me` 섹션이 아직 비어 있으면, 선택한 동안만 그 자리를 만들어 편집 경로를 안내한다. 비어 있는 섹션을 상시로 늘어놓지는 않는다.
- `Me` 섹션은 강조 디자인과 `내 챔피언 전용` 레이블로 구분하되 색상만으로 구분하지 않는다.
- 목차가 곧 어디에 작성된 내용이 있는지에 대한 안내다. 별도의 챔피언 목록 안내를 두지 않는다.
- 문서 하단에 현재 리비전, 마지막 갱신 시각, 마지막으로 반영한 사람, 패치 버전을 표시한다.
- 문서나 섹션이 비어 있을 때 다음 행동을 안내하는 빈 상태를 제공한다.
- 문서는 잘라 보여 주지 않고 전문을 표시한다. 게시판이 아니므로 목록·미리보기·상세의 구분이 없다.

### 5.4 문서 편집

- 로그인하지 않은 사용자도 문서를 조회할 수 있다. 편집에는 로그인이 필요하다.
- 편집 단위는 섹션 하나다. 문서 전체를 한 번에 고치지 않는다.
- 현재 페이지의 상대 포지션과 상대 챔피언은 자동 지정하며 편집 화면에서 바꿀 수 없다.
- `Me` 섹션을 새로 만들 때는 검색형 Combobox에서 내 챔피언을 고른다. 이미 섹션이 있는 챔피언은 중복 생성할 수 없다.
- 편집에는 편집 요약을 함께 받는다. 무엇을 왜 고쳤는지 남기기 위한 것이며 검토와 문서 역사에서 사용한다.
- 편집은 문서 화면 안이 아니라 **주소를 가진 별도 편집 화면**에서 한다. 왼쪽에 지금 문서, 오른쪽에 고치는 글을 나란히 놓는다.
- 편집 화면은 무엇이 달라졌는지 색으로 보여 준다. **더한 곳은 초록, 지운 곳은 빨간 형광펜**이며, 색을 못 보는 사람을 위해 밑줄과 취소선이 함께 간다.
- 최대 길이와 공백만 입력한 경우를 검증한다. 본문을 비운 제출은 섹션 삭제 제안으로 받아 검토로 보낸다.
- 저장 성공·실패 결과를 사용자에게 명확하게 알린다.

#### 5.4.1 즉시 반영과 검토

글을 더하는 것과 남이 쓴 글을 지우는 것은 위험의 크기가 다르다. 전자는 잃을 것이 없고
후자는 남의 글을 없앤다. 그래서 다르게 다룬다. 가르는 기준은 섹션의 상태가 아니라 **편집
자체가 무엇을 하는가**다.

- **지운 것이 없는 편집은 즉시 반영한다.** 검토를 기다리지 않는다. 빈 섹션을 처음 채우는 것도 여기에 해당한다.
- **지우거나 고치는 편집은 검토 대기로 보낸다.** 운영자가 승인해야 반영된다.
- 공백과 줄바꿈만 달라진 것은 지운 것으로 보지 않는다. 문단을 나누기만 해도 며칠을 기다리게 되면 아무도 다듬지 않는다.
- 운영자 본인의 편집은 제출과 동시에 반영된 것으로 기록한다. 자기 글을 자기가 검토하지 않는다.
- 어느 쪽이든 기여는 제안자 이름으로 기록한다.
- 지운 것이 있는지는 **저장 시점에 서버가 실제 본문과 비교해 판정한다.** 편집기가 보여 준 색은 미리보기일 뿐이며 클라이언트의 주장은 신뢰하지 않는다.
- **본문을 비우는 편집은 섹션 전체를 지우는 것이므로 언제나 검토 대기다.** 그렇게 하지 않으면 섹션을 비운 뒤 즉시 게시하는 검토 우회로가 열린다.

#### 5.4.2 편집 안내

- 어느 쪽에 해당하는지를 **쓰는 동안 내내** 보여 준다. 판정이 무엇을 쓰느냐에 달렸으므로 한 번 알리고 끝낼 수 없다. 저장하고 나서야 대기열로 갔다는 것을 알게 되면 기여가 끊긴다.
- 빨간 형광펜이 없으면 저장 시 즉시 반영된다는 사실을 알린다.
- 빨간 형광펜이 있으면 검토가 필요하며 며칠이 걸릴 수 있다는 사실과, 제출한 내용을 어디서 확인할 수 있는지 함께 알린다.

### 5.5 검토와 문서 역사

- 운영자는 대기 중인 편집 제안 목록을 오래된 순으로 확인할 수 있다.
- 검토 화면에는 제안 내용, 현재 문서 내용, 제안자, 편집 요약을 함께 표시한다. 검토에 올라오는 제안은 모두 무언가를 지우는 편집이므로, **무엇이 사라지는지를 형광펜으로 표시한다.**
- 운영자는 제안을 승인·거절할 수 있고, 승인 전에 내용을 고칠 수 있다.
- 제안이 작성된 시점의 리비전과 현재 리비전이 다르면 그 사실과 그 사이의 변경을 표시한다. **뒤처졌다는 이유만으로 자동 거절하지 않는다.** 반영 여부는 사람이 판단한다.
- 승인하면 문서에 반영되고 리비전이 1 오른다.
- 문서마다 리비전 목록과 각 리비전의 내용을 확인할 수 있다.
- 운영자는 문서를 이전 리비전으로 되돌릴 수 있다.
- 운영자는 최근 반영된 편집을 시간순으로 확인할 수 있으며, 검토를 거치지 않고 즉시 반영된 편집을 구분할 수 있어야 한다.
- 사용자는 자신이 제출한 제안의 처리 상태를 확인할 수 있다.

### 5.6 관리자 챔피언 분류

패치와 메타가 바뀌면 챔피언이 서는 포지션과 역할이 달라진다. 이를 **코드 배포 없이**
반영하는 것이 제품 목표 6이다.

#### 5.6.1 범위

관리자는 **이미 정의된 포지션과 카테고리에 챔피언을 배정**한다. 포지션·카테고리 기준
자체를 만들거나 없애는 것, 자동 분류, CSV 입출력, 다단계 승인은 비목표다 (3.2).

#### 5.6.2 챔피언 목록

- Data Dragon 동기화 결과를 기준으로 전체 챔피언을 보여 준다.
- 각 챔피언의 `챔피언 운영 상태`, `분류 검토 상태`, `데이터 소스 상태`와 현재 배정을 함께 표시한다.
- `미분류`, `검토 대기`, `소스 누락 검토 필요`를 기준으로 걸러 볼 수 있다. 손이 필요한 챔피언을 먼저 찾기 위한 것이다.
- 새로 동기화된 챔피언은 `검토 대기`로 들어온다. 관리자가 배정을 마치면 `검토 완료`가 된다.

#### 5.6.3 분류 배정

- 챔피언을 포지션과 카테고리에 배정하고 변경할 수 있다.
- 한 챔피언은 여러 포지션에 속할 수 있으나 **같은 포지션 안에서는 카테고리 하나뿐이다.** 서버에서 강제한다.
- 배정을 해제할 때는 레코드를 물리 삭제하지 않고 `분류 보관` 상태로 둔다. 이력과 참조를 잃지 않기 위해서다.
- 보관되지 않은 배정이 하나도 없는 챔피언은 `미분류`다. 이 상태는 저장하지 않고 도출한다.
- `분류 노출 상태`로 공개 목록 표시 여부를 정하고, 포지션 안에서의 표시 순서를 조정한다.
- `챔피언 운영 상태`를 비활성으로 두면 배정과 무관하게 공개 기능 전체에서 빠진다.

#### 5.6.4 안전장치

공개 화면을 즉시 바꾸는 기능이므로 다음을 갖춘다.

- 카탈로그에 없는 챔피언은 배정할 수 없다.
- 동기화 후 카탈로그에서 사라진 챔피언은 `소스 누락 검토 필요`로 표시하되 **공개 목록에서 자동으로 내리지 않는다.** 동기화 사고와 실제 삭제를 기계가 구분할 수 없으므로 사람이 판단한다.
- 모든 변경은 누가 언제 무엇을 바꿨는지 기록한다.
- 분류를 바꾸면 이미 작성된 상대법 문서의 접근 경로가 달라진다. 배정을 해제해도 문서는 지우지 않는다.

### 5.7 추후 개발 메뉴

- 글로벌 내비게이션에 `전적`, `통계`, `티어표` 메뉴를 표시한다.
- 각 메뉴는 `/records`, `/stats`, `/tier-list` 경로로 이동하며, MVP에서는 공통된 `추후 개발` 안내 화면을 제공한다.
- 안내 화면에는 선택한 메뉴명, 준비 중이라는 설명과 `상대법으로 돌아가기` 동작만 제공한다.
- MVP에서는 Riot API 호출, 검색 입력, 통계 수치, 차트나 티어 결과를 제공하지 않으며 가짜 데이터를 표시하지 않는다.
- 메뉴와 안내 화면은 키보드 접근, 현재 위치 표시, 모바일 내비게이션을 지원한다.

## 6. 핵심 사용자 흐름

### 흐름 A: 상대법 탐색

1. 사용자가 홈 화면에 진입한다.
2. 상대 챔피언이 플레이되는 포지션을 선택한다.
3. 선택한 포지션 안에서 상대 챔피언이 속한 카테고리를 선택한다.
4. 선택된 포지션·카테고리에 속한 챔피언 아이콘만 표시되는 것을 확인한다.
5. 아이콘 그리드에서 상대 챔피언을 찾거나 이름으로 검색한다.
6. 챔피언 아이콘을 선택한다.
7. 선택 애니메이션 후 해당 포지션의 챔피언 상대법 페이지로 이동한다.
8. Aside에서 챔피언의 정적 2D 일러스트와 스킬 정보를 확인하고, 기본 메뉴인 상대법 문서를 읽는다.
9. `Me` Combobox에서 자신의 챔피언을 선택한다.
10. 기존 `공통` 내용과 새로 드러난 자신의 챔피언 전용 `Me` 내용을 함께 확인한다.

### 흐름 B: 내용 더하기

1. 사용자가 섹션의 편집 버튼을 선택해 편집 화면으로 이동한다.
2. 로그인이 필요하면 로그인 후 원래 편집 흐름으로 돌아온다.
3. 오른쪽에 내용을 더한다. 더한 곳이 초록으로 칠해지고, 저장하면 바로 반영된다는 안내를 확인한다.
4. 편집 요약을 입력하고 저장한다.
5. 문서로 돌아가 자신의 내용이 즉시 반영된 것을 확인한다.

### 흐름 C: 이미 쓰인 내용 고치기

1. 사용자가 섹션의 편집 버튼을 선택해 편집 화면으로 이동한다.
2. 내용을 지우거나 고친다. 사라지는 곳이 왼쪽에서 빨갛게 칠해지고, 검토를 거쳐 반영되며 며칠이 걸릴 수 있다는 안내로 바뀐다.
3. 편집 요약과 함께 제출한다.
4. `내 편집`에서 제안이 대기 중임을 확인한다.
5. 운영자가 승인하면 문서에 반영되고, 문서 역사에 자신의 이름으로 기록된다.

### 흐름 D: 검토 (운영자)

1. 운영자가 대기 중인 편집 제안 목록을 연다.
2. 제안 내용과 현재 문서 내용을 나란히 놓고, 형광펜으로 무엇이 사라지고 무엇이 더해지는지 확인한다.
3. 제안이 뒤처졌다면 그 사이의 변경을 확인한다.
4. 그대로 반영하거나, 고쳐서 반영하거나, 사유와 함께 거절한다.

## 8. 콘텐츠 및 데이터 요구사항

### 포지션

- 고유 식별자와 URL용 슬러그
- 표시 이름: 탑, 정글, 미드, 원딜, 서폿
- 정렬 순서와 활성 여부

### 카테고리

- 고유 식별자와 URL용 슬러그
- 소속 포지션 ID
- 표시 이름: 탱커, 딜탱, 딜러, AD, AP, 암살자, 메이지, 브루저/원딜, 원딜, Mom, Dad, Wtf?!
- 대표 이미지 경로와 대체 텍스트
- 정렬 순서와 활성 여부

### 챔피언

- 고유 식별자
- 한글 이름 및 영문 이름
- URL에 사용할 고유 슬러그
- 1:1 아이콘 이미지 경로와 대체 텍스트
- 정적 2D 일러스트 경로, 원본 크기, 대체 텍스트 및 사용 권한 확인 상태
- 데스크톱·모바일 크롭에 사용할 챔피언별 초점 위치
- 정렬 순서
- `챔피언 운영 상태` (활성 / 비활성)
- `분류 검토 상태` (검토 대기 / 검토 완료)
- `데이터 소스 상태` (정상 / 소스 누락 검토 필요)

### 포지션별 챔피언 분류

관리자 화면이 이 데이터를 고친다 (5.6). 코드가 아니라 저장소에 두어야 배포 없이 갱신할 수 있다.

- 포지션 ID, 카테고리 ID와 챔피언 ID
- 해당 포지션에서의 `분류 노출 상태`와 정렬 순서
- `분류 보관` 여부와 보관 시각
- 생성·수정 시각과 마지막으로 바꾼 관리자 ID
- 하나의 챔피언은 여러 포지션에 속할 수 있지만 같은 포지션 안에서는 하나의 카테고리에만 속한다.
- `미분류`는 저장하지 않는다. 보관되지 않은 배정이 하나도 없는 상태에서 도출한다.

### 분류 변경 이력

- 대상 챔피언 ID와 포지션 ID
- 변경 전후의 카테고리·노출 상태·순서
- 변경한 관리자 ID와 변경 시각

### 스킬

- 고유 식별자
- 챔피언 ID
- 슬롯과 표시 순서(Q, W, E, R)
- 스킬명과 1:1 아이콘 경로
- 재사용 대기시간, 소모값, 범위, 상세 설명
- 데이터 패치 버전과 갱신 시각

### 문서

- 고유 식별자
- 상대 포지션 ID와 상대 챔피언 ID (이 조합이 유일하다)
- `공통` 섹션 내용
- 현재 리비전
- 시즌 또는 패치 버전
- 편집 정책 (`guarded`, `open`, `locked`)
- 생성·수정 시각과 마지막으로 반영한 사용자 ID

### Me 섹션

- 상위 문서 ID와 내 챔피언 ID (이 조합이 유일하다)
- 해당 챔피언에만 적용되는 내용
- 수정 시각과 마지막으로 반영한 사용자 ID

### 편집 제안

승인된 제안이 곧 문서의 리비전이다. 대기열과 역사를 같은 기록으로 다룬다.

- 고유 식별자와 대상 문서 ID
- 대상 섹션 (`공통`이면 비워 둔다)
- 제안을 작성할 때 기준으로 삼은 리비전
- 섹션 전문. 차이가 아니라 전체 내용을 저장해 특정 리비전을 되짚을 수 있게 한다
- 편집 요약
- 처리 상태 (`대기`, `승인`, `거절`, `철회`)
- 제안자 ID와 제출 시각
- 승인 경로 (`빈 곳 채움`, `더하기만`, `검토 승인`, `운영자 편집`)
- 검토 시각, 검토자 ID, 검토 메모
- 승인된 경우 이 제안이 만든 리비전 번호

### 영상

- 고유 식별자, 상대 포지션 ID와 상대 챔피언 ID
- 제목, 썸네일, 영상 제공자 및 외부 영상 ID 또는 URL
- 게시 상태와 표시 순서

### 사용자

- 고유 식별자
- 인증 제공자(`구글`, `카카오`)와 제공자별 사용자 ID. 이 조합이 유일하다
- 표시 이름
- 이메일. 제공자가 인증된 값을 줄 때만 저장한다. 카카오는 선택 항목이라 비어 있을 수 있다
- 역할(일반 사용자, 관리자)
- 가입·수정 시각

같은 사람이 구글과 카카오로 각각 가입하면 서로 다른 사용자가 된다. 이번 범위에서는 이를 허용하되,
이후 계정 연결의 근거로 쓰기 위해 이메일을 보관한다. 이메일로 계정을 자동 병합하지는 않는다.

## 9. UX/UI 요구사항

- 사이트의 핵심 시각 요소는 챔피언 일러스트이며, 텍스트와 버튼은 이미지 위에서도 충분한 대비를 가져야 한다.
- 카드 이미지는 1:1 컨테이너 안에서 일관되게 잘라 표시하되 얼굴이나 핵심 피사체가 과도하게 잘리지 않도록 이미지별 초점 위치를 조정할 수 있어야 한다.
- 카드의 기본, 호버, 포커스, 선택 상태를 서로 구분한다.
- 포지션 메뉴는 현재 선택을 명확히 표시하고 키보드와 모바일 터치로 전환할 수 있어야 한다.
- 카테고리 선택 이후에는 선택된 포지션과 카테고리명을 계속 노출하고, `포지션·카테고리 변경` 동작을 쉽게 찾을 수 있게 한다.
- 포지션 또는 카테고리 전환 시 이전 선택의 챔피언 아이콘이나 검색 결과가 남아 있지 않아야 한다.
- 데스크톱에서는 챔피언 Aside와 콘텐츠 Main을 나란히 배치하고, 좁은 화면에서는 Aside를 Main 위로 이동한다.
- 챔피언명에는 키치한 디스플레이 글꼴과 장식 효과를 사용할 수 있지만, 본문과 스킬 설명에는 가독성 높은 글꼴을 사용한다.
- `공통`과 새로 드러난 `Me` 내용은 배경, 레이블, 아이콘 등 두 가지 이상의 단서로 구분한다.
- 스킬 상세 팝오버는 화면 밖으로 잘리지 않고, 한 번에 하나만 열리며, Escape 키와 외부 클릭으로 닫혀야 한다.
- 모든 인터랙티브 요소는 키보드로 접근할 수 있고 눈에 보이는 포커스 표시를 제공한다.
- 이미지를 불러오지 못해도 챔피언 이름과 대체 UI로 기능을 사용할 수 있어야 한다.
- 버튼 문구는 `편집`, `저장`, `제안 제출`, `승인`, `거절`처럼 행동을 직접 설명한다.
- 즉시 반영되는 편집과 검토를 거치는 편집은 편집하는 동안 내내 서로 다른 안내로 구분하고, 내용이 바뀌면 안내도 함께 바뀐다.
- 편집 형광펜은 색과 함께 밑줄·취소선을 쓴다. 무엇이 사라지는지가 이 화면의 요점이라 색만으로 전달하면 안 된다.
- 검토 대기 중인 제안은 사용자가 자신의 것임을 알아볼 수 있게 표시한다.
- 삭제처럼 되돌리기 어려운 행동에는 확인 단계를 제공한다.

## 10. 비기능 요구사항

### 성능

- 운영 환경의 모바일 75백분위 기준 LCP 2.5초 이내, CLS 0.1 이하를 목표로 한다.
- 카드 이미지는 적절한 크기와 포맷으로 제공하고, 첫 화면 밖 이미지는 지연 로딩한다.
- Aside 일러스트는 적절한 크기의 AVIF 또는 WebP와 호환용 대체 포맷을 제공하고, 반응형 이미지 후보를 사용해 화면보다 큰 원본을 불필요하게 전송하지 않는다.
- 첫 화면에 보이는 Aside 일러스트의 표시 크기를 미리 예약하고 로딩 우선순위를 명시해 LCP와 CLS를 관리한다.
- 검색 입력과 필터 변경 시 불필요한 전체 페이지 새로고침을 피한다.

### 접근성

- 주요 기능은 키보드만으로 사용할 수 있어야 한다.
- 이미지에 의미 있는 대체 텍스트를 제공한다.
- 색상만으로 상태를 전달하지 않는다.
- 애니메이션 감소 환경에서는 카드 전환과 장식 효과를 중지하거나 최소화한다.
- 스킬 설명은 hover에만 의존하지 않고 focus와 tap으로도 제공한다.

### 보안 및 운영

- 인증 및 권한 검증은 화면 표시 여부와 별개로 서버에서 수행한다.
- 지운 것이 있는지에 대한 판정은 서버가 저장 시점의 실제 본문과 비교해 수행한다. 즉시 반영과 검토를 가르는 판정이므로 클라이언트가 보여 준 색을 신뢰하지 않는다. 클라이언트와 서버는 같은 비교 함수를 쓴다.
- 즉시 반영되는 면이 넓어졌다. 예전에는 빈 섹션뿐이었지만 이제 모든 문서의 모든 섹션이 덧붙이기에 열려 있다. 아래 세 장치의 중요성이 그만큼 커진다.
- 검토 없이 즉시 반영되는 경로가 있으므로, 다음 세 가지를 함께 갖춘다. 하나라도 없으면 이 정책은 안전하지 않다.
  - 운영자가 최근 반영된 편집을 훑어볼 수 있는 최근 변경 화면
  - 문서를 이전 리비전으로 한 번에 되돌리는 수단
  - 계정당 시간당 편집 제출 수 제한
- 도배가 발생한 문서는 편집 정책을 `locked`로 좁혀 대응한다. 문서 단위로 좁힐 수 있으므로 서비스 전체를 잠그지 않는다.
- 편집 내용은 저장·출력 단계에서 스크립트 삽입 공격을 방지하도록 처리한다.
- 로그인, 편집 제출, 검토 API에는 요청 제한과 기본적인 남용 방지 수단을 적용한다.
- 오류 화면에 내부 경로나 비밀값을 노출하지 않는다.
- 삭제 정책, 신고 절차, 개인정보 처리 범위를 출시 전에 문서화한다.

### 호환성

- 최신 Chrome, Edge, Safari, Firefox의 현재 및 직전 주요 버전을 지원 대상으로 한다.
- 모바일 터치 환경과 데스크톱 마우스 환경을 모두 지원한다.
- 챔피언 일러스트는 표준 HTML 이미지 요소로 제공하고, 최신 이미지 포맷을 지원하지 않는 브라우저에는 호환 포맷을 제공한다.

## 12. 출시 완료 기준

- P0 기능 요구사항이 모두 구현되고 주요 사용자 흐름 테스트를 통과한다.
- 탑, 정글, 미드, 원딜, 서폿 메뉴가 표시되고 기본 미드 선택과 URL 상태 복원이 동작한다.
- 탑의 Moondo·Aatrox·Teemo, 정글의 Leesin·lillia, 미드의 Zed·Zoe·yone, 원딜의 Caitlyn, 서폿의 lulu·Blitz 이미지가 지정된 카테고리에 올바르게 표시된다.
- 각 포지션과 카테고리에서 소속 챔피언만 노출되며, 포지션 → 카테고리 → 챔피언 → 문서 → 편집 흐름을 검증한다.
- 아리 페이지에서 목업 구도를 따른 정적 2D 일러스트, 키치한 챔피언명, Q·W·E·R 스킬 아이콘과 상세 설명이 올바르게 표시된다.
- 아리 페이지 최초 진입 시 상대법 문서가 표시되고, 영상 탭으로 전환한 뒤 상태를 복원할 수 있다.
- 공통 섹션과 내용이 있는 Me 섹션이 목차 하나를 가진 한 문서로 표시되고, 트위스티드 페이트를 선택하면 그 섹션의 제목으로 이동한다.
- 제목에 1, 1.1, 1.1.1 번호가 매겨지고, 목차로 이동하며, 접힌 제목으로 이동하면 펼쳐지는 것을 확인한다.
- 주석 표식에 마우스를 올리면 내용이 그 자리에 뜨고, 다른 매치업 문서로 가는 링크와 아직 없는 문서가 구분되어 보이는 것을 확인한다.
- 구글과 카카오 각각으로 로그인·로그아웃이 동작한다.
- 이미 쓰인 섹션에 지운 것 없이 더하기만 하면 즉시 반영되고, 한 낱말이라도 지우거나 고치면 검토 대기로 들어가는 것을 확인한다.
- 공백과 줄바꿈만 바꾼 편집이 즉시 반영되는 것을 확인한다.
- 편집 화면에서 더한 곳이 초록, 지운 곳이 빨강으로 칠해지고, 지우는 순간 안내가 검토 대기로 바뀌는 것을 확인한다.
- 섹션을 비우는 편집이 검토 대기로 가는 것을 확인한다. 검토 우회로가 없어야 한다.
- 운영자가 제안을 승인·거절할 수 있고, 승인 시 기여가 제안자 이름으로 기록되는 것을 확인한다.
- 기준 리비전이 뒤처진 제안이 자동 거절되지 않고 검토 화면에 그 사실이 표시되는 것을 확인한다.
- 문서 역사와 되돌리기, 최근 변경, 제출 수 제한이 동작한다.
- 모바일과 데스크톱 지원 브라우저에서 치명적인 UI 오류가 없다.
- 로그인하지 않은 편집 제출과 운영자가 아닌 검토 시도가 서버에서 차단된다.
- 관리자가 아닌 사용자의 분류 관리 화면·API 접근이 서버에서 차단된다.
- 관리자 화면에서 챔피언의 포지션·카테고리를 바꾸면 **재배포 없이** 공개 선택 화면에 반영된다.
- 같은 포지션에 카테고리를 둘 이상 배정하려는 시도가 차단된다.
- 배정을 해제한 챔피언이 미분류로 구분되고, 보관된 배정 기록이 남아 있다.
- 기본적인 악성 입력이 차단된다.
- 로딩, 빈 상태, 오류 상태가 각 핵심 화면에 구현되어 있다.
- 전적, 통계, 티어표 메뉴가 고유 URL의 `추후 개발` 안내 화면으로 이동하고 실제 데이터나 가짜 수치를 표시하지 않는다.
- 이미지 사용 권한, 운영 정책, 개인정보 관련 고지 사항을 확인한다.

| 위험 | 영향 | 대응 방향 |

| 편집 분쟁 | 같은 섹션을 두고 되돌리기가 반복됨 | 편집 요약과 문서 역사로 경위를 남기고, 반복되면 토론 절차 도입을 검토한다. |
| 잘못되거나 오래된 공략 | 사용자 신뢰 저하 | 작성·수정일을 명확히 표시하고 추후 패치 버전과 추천 기능을 도입한다. |
| 악성 편집과 스팸 | 커뮤니티 품질 저하 | 입력 제한, 요청 제한, 신고, 관리자 기능을 단계적으로 적용한다. |
| 이미지 저작권 또는 사용 조건 | 공개 운영 제약 | Data Dragon 등 Riot이 지원하는 출처를 우선하고 사용 조건을 출시 전에 검토하며 교체 가능한 데이터 구조를 사용한다. |
| 과도한 애니메이션 | 탐색 지연 및 접근성 저하 | 애니메이션 시간을 짧게 유지하고 감소 모드를 지원한다. |
| 대형 2D 일러스트 용량 | 모바일 LCP 지연과 데이터 사용량 증가 | 반응형 이미지, 차세대 포맷, 압축과 표시 크기 예약을 적용한다. |
| 일러스트 크롭 불일치 | 챔피언 얼굴이나 핵심 피사체가 화면에서 잘림 | 챔피언별 초점 위치를 데이터로 관리하고 주요 반응형 구간을 시각 검수한다. |
| 포지션별 챔피언 분류 변경 | 패치와 메타 변화 후 잘못된 카테고리에 노출됨 | 포지션·카테고리 매핑을 데이터로 관리하고 패치마다 운영자가 검토한다. |

| 동기화 사고로 챔피언이 사라짐 | 잘못된 자동 판단으로 공개 목록에서 대량 이탈 | 카탈로그에서 사라진 챔피언을 표시만 하고 자동으로 내리지 않는다. 사람이 판단한다 (FR-41). |

## 15. 미결정 사항

다음 항목은 구현 착수 전에 제품 결정이 필요하다.

1. 전체 챔피언의 포지션별 카테고리 배정표와 신규·역할 변경 챔피언의 분류 기준. 갱신 수단은 관리자 화면(5.6)으로 정해졌으나 **어떤 기준으로 배정할지는 미정**이다
2. 챔피언 정적 2D 일러스트의 출처, 기본 스킨 범위, 사용 권한 및 크롭 기준
3. 키치한 챔피언명에 사용할 한글 디스플레이 글꼴과 웹폰트 라이선스
4. Data Dragon 갱신 주기와 스킬 수치·설명 보정 책임자
5. 섹션 내용의 최소·최대 길이 및 마크다운 지원 여부
6. 편집 요약의 필수 여부와 최대 길이
7. 계정당 시간당 편집 제출 수의 구체적인 상한
8. 검토 대기 제안의 자동 만료 기간 (방치된 제안을 언제까지 둘지)
9. 영상의 출처, 임베드 허용 범위 및 등록·검수 주체
10. 초기 운영자가 준비할 시드 문서와 영상의 범위
11. 토론, 신고, 관리자 기능 도입 일정과 운영 여력
12. 구글·카카오 계정 연결 기능의 도입 시점과 병합 기준

## 16. 전제

- 서비스 언어는 우선 한국어로 제공한다.
- MVP는 탑, 정글, 미드, 원딜, 서폿 다섯 포지션을 지원하고 URL에 포지션 문맥을 유지한다.
- 하나의 챔피언은 여러 포지션에 속할 수 있지만 같은 포지션 안에서는 정확히 하나의 카테고리에 속한다.
- 포지션별 카테고리명과 대표 이미지 경로는 5.1의 표를 기준으로 사용한다.
- 카테고리에서 선택해 진입한 챔피언은 사용자가 상대할 챔피언이다. 예를 들어 아리 페이지의 문서는 아리를 상대하는 방법을 다룬다.
- 매치업 하나에 문서는 정확히 하나다. 문서는 특정 작성자의 것이 아니라 공동 소유다.
- `공통`은 내 챔피언과 무관하게 항상 표시하고, `Me`는 사용자가 내 챔피언을 선택했을 때 일치하는 섹션만 추가로 표시한다.
- 편집은 섹션 단위로 이루어진다. 빈 섹션을 채우는 편집과 이미 쓰인 섹션을 고치는 편집은 다르게 다룬다.
- 스킬 아이콘 네 개는 Q, W, E, R을 의미하며 패시브는 MVP에서 표시하지 않는다.
- 스킬 아이콘과 상세 정보는 패치 버전을 고정한 Riot Data Dragon을 사용한다.
- 챔피언 Aside는 권리 확인된 정적 2D 일러스트로 통일하며 3D 모델과 WebGL을 도입하지 않는다.
- Riot IP와 데이터를 사용하는 공개 서비스에는 적용되는 Riot 정책에 따른 비공식 프로젝트 고지를 표시하고 출시 전 사용 조건을 재검토한다.
- 읽기는 공개하고, 편집에는 로그인을 요구한다.
- 검토 권한은 초기에 운영자 1인이 가진다. 검토자 확대는 운영 부담을 보고 판단한다.
