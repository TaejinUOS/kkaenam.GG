## 2. 임시 구현 — 실서비스 전 반드시 교체

### 2.1 인증과 Tip 저장 ← 가장 중요

**지금 상태.** 서버가 없다. Tip 작성·수정·삭제·좋아요·싫어요가 전부 브라우저
`localStorage`에서만 동작한다. 로그인은 닉네임만 입력하면 만들어지는 **로컬 데모 계정**이고,
비밀번호도 검증도 없다.

**왜 이렇게 두었나.** PRD 15 미결정 1번(회원가입 방식: 자체 계정 / 소셜 로그인 / 기타)이
정해지기 전에는 실제 인증을 설계할 수 없다. 흐름만 검증할 수 있게 해 두고 화면에도
`로컬 데모 계정 · 작성한 Tip은 이 브라우저에만 저장됩니다`라고 표시한다.

**그래서 지금 이런 일이 벌어진다.**

- 다른 사람이 쓴 Tip을 볼 수 없다. 브라우저를 바꾸면 내가 쓴 Tip도 사라진다.
- 시드 Tip 15개의 좋아요 수는 고정값이고, 내 평가는 그 위에 +1로만 얹힌다.
- 시크릿 창이나 저장소를 막은 브라우저에서는 작성 기능이 조용히 동작하지 않는다.

**교체 방법.** [`src/lib/tipStore.ts`](../src/lib/tipStore.ts)의 함수 시그니처를 그대로 두고
내부를 `fetch` 호출로 바꾸면 화면 코드는 손대지 않아도 된다.

| 함수 | 대응 API |
| --- | --- |
| `loadUserTips` / `saveUserTip` / `deleteUserTip` | Tip 조회 · 생성 · 수정 · 삭제 |
| `loadVotes` / `toggleVote` | 평가 등록 · 변경 · 취소 |
| `loadUser` / `signIn` / `signOut` | 세션 |

> **주의.** 화면에서 수정·삭제 버튼을 숨기는 것은 편의일 뿐이다. PRD 10 "보안 및 운영"과
> FR-17에 따라 **작성자 권한은 서버에서 반드시 다시 검증해야 한다.** Tip 본문의 스크립트
> 삽입 방지와 요청 제한도 서버 작업으로 남아 있다.

### 2.2 영상 탭

`영상` 탭은 **빈 상태 안내만** 보여 준다. 가짜 썸네일이나 임시 영상은 넣지 않았다.
PRD 3.2가 가짜 데이터를 금지하고, 영상의 출처·임베드 허용 범위·등록 검수 주체가
PRD 15 미결정 8번으로 남아 있기 때문이다.

블루프린트 6.4의 2열 골격은 자리만 잡아 두었으니, 출처가 정해지면
[`src/components/matchup/VideoPanel.tsx`](../src/components/matchup/VideoPanel.tsx)에
목록을 채우면 된다. 데이터 형태는 PRD 8장 "영상" 항목을 따른다.

### 2.3 입력 길이 제한이 잠정값이다

[`TipForm.tsx`](../src/components/matchup/TipForm.tsx)의 `LIMITS` 상수는 PRD 15
미결정 6·7번이 정해지기 전까지 쓰는 임시값이다.

| 항목 | 현재 값 |
| --- | --- |
| 제목 | 4 ~ 60자 |
| General | 20 ~ 1500자 |
| Me 블록 내용 | 10 ~ 800자 |
| Tip 하나당 Me 블록 | 최대 10개 |

마크다운 지원 여부(미결정 6번)도 아직 결정되지 않아 지금은 평문으로만 저장하고
줄바꿈만 유지한다.

| 26 ~ 31행 | 용어 6개 — `챔피언 운영 상태`, `분류 검토 상태`, `데이터 소스 상태`, `분류 노출 상태`, `분류 보관`, `미분류` | 삭제된 관리자 절에서만 쓰이던 용어 |

| 82행 | 대상 사용자의 "운영 사용자" | 위와 같음 |
| 89행 | 주요 사용 상황 "관리자가 신규·역할 변경 챔피언을 찾아 분류하고…" | 위와 같음 |

**특히 56행이 중요하다.** 현재 챔피언 분류는
[`src/data/taxonomy.ts`](../src/data/taxonomy.ts)를 고쳐 배포하는 방식이라
"배포 없이"라는 목표를 만족하지 못한다. 둘 중 하나를 골라야 한다.

1. **관리자 화면을 다시 범위에 넣는다** — 삭제한 절을 복원하고 분류 관리 UI와 API를 만든다.
2. **목표에서 "배포 없이"를 뺀다** — 지금처럼 데이터 파일 + 점검 스크립트로 운영한다.
   패치마다 운영자가 검토한다는 PRD 14의 위험 대응은 이 방식으로도 지켜진다.

> 위 표의 나머지 "관리자" 언급(FR-21, 8장 사용자 역할, 13장 향후 확장, 14장 위험, 15장
> 미결정 11번)은 삭제된 절과 무관하게 여전히 유효하니 손대지 않아도 된다.

## 5. 운영하면서 알아야 할 것

### 5.1 `dev`와 `build`를 동시에 돌리지 말 것

둘 다 같은 `.next` 디렉터리를 쓴다. dev 서버를 켠 채 `npm run build`를 돌리면 dev 서버가
빈 페이지나 500을 뱉기 시작한다. 이 경우 **코드 문제가 아니다.** dev 서버를 끄고
`.next`를 지운 뒤 다시 켜면 된다.

```bash
rm -rf .next && npm run dev
```

### 5.2 패치 갱신

```bash
DDRAGON_PATCH=16.18.1 npm run data:sync   # 챔피언·스킬 다시 내려받기
npx tsx scripts/check-taxonomy.ts          # 이름이 깨지지 않았는지 점검
```

패치 버전과 갱신 시각은 `src/data/generated/champions.json`에 저장되고 사이트 하단에
표시된다. 신규 챔피언이 나오면 `taxonomy.ts`에 직접 배정해야 목록에 나온다.

### 5.3 챔피언 분류 갱신

포지션·카테고리와 챔피언 명단은 [`src/data/taxonomy.ts`](../src/data/taxonomy.ts)
**한 곳에서만** 관리한다. 화면 코드에 챔피언을 개별로 고정하지 않는다 (PRD 5.1).

- 이름은 Data Dragon `ko_KR` 표기와 **정확히** 일치해야 한다. `리 신`, `트위스티드 페이트`,
  `아우렐리온 솔`, `문도 박사`처럼 띄어쓰기가 있는 이름을 조심할 것.
- 틀리면 앱이 뜰 때 오류로 잡히고, `check-taxonomy.ts`가 어떤 이름인지 알려 준다.
- 한 챔피언이 여러 포지션에 속할 수 있지만 **같은 포지션 안에서는 카테고리 하나뿐**이다.
  점검 스크립트가 중복도 잡는다.
- 분류에 없는 조합(`/matchup/mid/leesin` 같은)은 404가 된다. 의도된 동작이다 (FR-07).

### 5.4 외부 의존성

| 대상 | 출처 | 확인해야 할 것 |
| --- | --- | --- |
| 챔피언 아이콘 · 일러스트 · 스킬 아이콘 | Riot Data Dragon CDN | 런타임에 외부 요청. 오프라인·차단 환경에서는 대체 UI가 뜬다 |
| Pretendard (본문) | jsDelivr CDN | 서체 라이선스 확인 (블루프린트 10장) |
| IBM Plex Mono (수치) | Google Fonts (`next/font/google`) | OFL |
| **SB 어그로체 B (제목)** | `src/app/fonts/SBAggroB.woff` self-host | **파일을 수정·서브셋하지 말 것.** 라이선스가 폰트 파일의 수정·복제·배포를 금지한다. 235KB를 통째로 전송하므로 LCP 예산에 포함해 볼 것 |
| 카테고리 대표 이미지 12장 | `public/images/` (직접 보유) | **사용 권리 확인이 끝나지 않았다** |

Riot 비공식 프로젝트 고지는 사이트 하단에 이미 넣어 두었다 (PRD 16).
공개 배포 전에 Riot 정책을 다시 검토할 것.

### 5.5 모바일 헤더 메뉴가 가로로 넘친다

360px에서 메뉴 다섯 개(`상대법 / 전적 / 통계 / 티어표 / 강의`)의 폭이 254px인데
로고와 마이페이지 아바타를 빼면 172px만 남는다. 세 개 반만 보이고 나머지는 가로 스크롤이다.
오른쪽 끝을 흐리게 처리해 더 있다는 것은 알 수 있게 했다.

글자와 여백을 최대로 줄여도 82px이 모자라므로, 제대로 풀려면 둘 중 하나가 필요하다.

1. 모바일에서 햄버거 메뉴로 전환한다 (블루프린트에 모바일 헤더 규격이 없어 새로 정해야 함)
2. 모바일 헤더에서는 `강의`처럼 우선순위가 낮은 항목을 빼고 마이페이지 안으로 옮긴다

지금은 스크롤로 모든 메뉴에 닿을 수 있어 기능상 막힌 곳은 없다.

### 5.6 브라우저 저장소 키

로컬 데모 데이터를 지우려면 개발자 도구에서 아래 키를 삭제하면 된다.

```
kkaenam.tips.v1     내가 쓴 Tip
kkaenam.votes.v1    좋아요 · 싫어요
kkaenam.user.v1     로컬 데모 계정
```
