# Riot 제품 심사·수익화와 전적 기능 준비

기록일·공식 자료 확인일: 2026-09-05

이 문서는 Riot 제품 심사와 수익화에 관한 대화 내용, 준비 목표와 후속 작업을 모은다.
기능 범위의 기준은 [PRD.md](./PRD.md)이며, 이 기록으로 전적·광고 구현을 MVP에 추가하지 않는다.
포털에 로그인해 신청 상태를 확인하거나 신청서를 제출한 작업은 이번 대화에서 수행하지 않았다.

## 1. 목표와 현재 상태

우선 목표는 현재 운영 중인 **상대법 위키를 Riot에 등록·검토받고, 광고 수익화를 진행할 조건을 확인하는 것**이다.
전적 검색은 별도의 후속 기능 후보로 둔다. 수익화를 위해 전적 기능부터 만들 필요는 없다.

| 항목 | 현재 파악한 상태 / 목표 |
| --- | --- |
| 서비스 | 깨남.COM — 한국어 LoL 상대법 위키, `https://kkaenam.com` |
| 주요 기능 | 포지션별 탐색, 공통·Me 상대법, 공동 편집과 운영자 검토 |
| Riot 데이터 | Data Dragon의 챔피언·스킬 정보와 이미지 사용 |
| 전적 | `/records` 안내 화면만 제공. 실제 데이터 조회는 후속 범위 |
| 수익 모델 | 무료 열람 + 사이트 광고를 우선 검토. 광고 제공자·배치·도입 시점은 미정 |
| 제품 등록·심사 상태 | **미확인.** 미신청 또는 승인 완료라고 추정하지 않는다 |
| Production API 키 보유 여부 | **미확인.** 제품 상태와 별도로 확인한다 |
| 다음 완료 기준 | 실제 포털 상태·Riot 답변을 확인하고 허용되는 수익화 범위와 남은 조건을 기록한다 |

## 2. 정책에서 구분할 것

### 제품 상태와 API 키

Riot 개발자 일반 정책은 제품을 Developer Portal에 등록하고 심사받도록 규정한다.
LoL 문서는 공식 API 사용 여부와 관계없이 플레이어 대상 제품을 등록하도록 명시한다.
수익화 조건에는 제품 상태가 `Approved` 또는 `Acknowledged`일 것이 포함된다.
무료 이용 범위를 제공해야 하며, 여기에 광고를 포함할 수 있다. 유료 콘텐츠에는 추가 가치가 있어야 한다.
근거: [일반 정책](https://developer.riotgames.com/policies/general), [LoL 등록·수익화 정책](https://developer.riotgames.com/docs/lol#registration).

전적 API의 공개 운영에는 Production 키가 필요하다. 개발용 키는 24시간마다 만료되고,
개인용 키는 공개 서비스나 공개 알파·베타에 사용할 수 없다.
제품 상태가 승인됐다고 Production 키와 해당 권한까지 확보한 것으로 간주하지 않는다.
근거: [API 키 안내](https://developer.riotgames.com/docs/portal#api-keys).

### 광고 예외와 남은 해석

일반 팬 콘텐츠 정책은 개인의 팬 프로젝트에 적절한 광고로 수익을 얻는 예외를 둔다.
다만 이 예외가 Data Dragon 기반 깨남.COM의 제품 등록·수익화 요건을 면제한다고 단정하지 않는다.
현재 위키와 광고 모델을 설명하고 적용 조건을 Riot에 확인하는 것을 준비 방향으로 삼는다.
근거: [Legal Jibber Jabber의 광고 예외](https://www.riotgames.com/en/legal).

API를 사용하지 않는 위키가 구체적으로 어느 등록 유형·상태로 처리되는지,
`Approved`와 `Acknowledged` 중 어느 결과를 받는지는 확인한 공개 문서만으로 확정할 수 없다.
실제 신청 화면과 Riot 답변에 따라 기록을 보완한다.

### 심사 전후의 실제 차이

| 항목 | 심사 통과 전 | 통과 후 |
| --- | --- | --- |
| 사이트 기능 | 현재 구현 상태 | 승인만으로 기능이 자동 추가되지는 않음 |
| 수익화 | 개발자 정책의 승인 상태 요건 충족 여부를 확인해야 함 | `Approved` 또는 `Acknowledged` 확인 후 다른 조건도 지키며 진행 |
| 전적 공개 | 개발용·개인용 키로 공개 운영 불가 | Production 키와 권한 확보 후 구현·검증을 거쳐 공개 |
| 호출 한도 | 보유 키의 제한 적용 | Production 키 발급 시 더 높은 한도 적용. 실제 할당값 확인 필요 |
| 운영 의무 | 등록·정책 검토 필요 | 정책 준수 지속, 새 기능·변경 사항도 제품 페이지를 통해 검토 |

승인은 Riot 공식 서비스·제휴사 지위를 뜻하지 않는다. 비공식 서비스 고지를 유지한다.
위 표의 정책 근거는 [일반 정책](https://developer.riotgames.com/policies/general)과
[API 키 안내](https://developer.riotgames.com/docs/portal#api-keys)다.

## 3. 신청 준비와 절차

1. [Developer Portal](https://developer.riotgames.com/)에 Riot 계정으로 로그인해 기존 제품 등록 여부를 확인한다.
2. 새 등록이 필요하면 `Register Product` / `Register Project`에서 실제 제공되는 유형을 확인한다.
   공개 위키와 광고 계획을 명시하고, 맞는 유형이 불명확하면 개발자 지원으로 문의한다.
3. 제품 주소, 사용자에게 주는 가치, 구현된 기능, 데이터 출처와 수익 모델을 작성한다.
   현재 기능과 향후 전적 계획을 구분한다.
4. 실제 사이트와 핵심 사용 흐름, 이용약관·개인정보처리방침·비공식 고지를 준비한다.
   로그인 뒤 편집·검토 흐름은 시연 영상 등을 보충 자료로 준비할 수 있다.
5. 소유권 인증이 요구되면 포털이 제공한 문자열을 지정 주소에서 읽을 수 있게 배포하고 인증 상태를 확인한다.
   Production 신청은 사이트 인증 전에는 처리되지 않는다.
6. 신청을 제출하고 보완 요청·승인 결과를 확인한다. 승인 상태와 키 발급 결과를 각각 기록한다.
7. 광고 도입 전에 실제 승인 조건과 수익 모델이 일치하는지 확인한다. 이후 전적 등 기능 추가도 제품 정보에 반영해 검토받는다.

등록 절차: [Developer Portal 안내](https://developer.riotgames.com/docs/portal#application-process).
Production 심사에서는 작동하는 사이트가 필요하며 GitHub 소스만으로 대체할 수 없다:
[Production 신청 FAQ](https://support-developer.riotgames.com/hc/en-us/articles/22801383038867-Production-Key-Applications).
인증 방식: [소유권 인증 FAQ](https://support-developer.riotgames.com/hc/en-us/articles/22801461443091-Verification-for-Production-Applications).

신규 문의는 [Developer Relations 지원 사이트](https://support-developer.riotgames.com/)를 사용한다.
기존 앱 메시지는 신규 발신이 제한되는 방향으로 전환됐으며, 결과·보완 요청은 포털 안내도 확인한다.
근거: [문의 방식 변경 안내](https://support-developer.riotgames.com/hc/en-us/articles/28593035600531-App-Messaging-Deprecation).

처리 기간은 확정하지 않는다. [공식 응답 기간 FAQ](https://support-developer.riotgames.com/hc/en-us/articles/22801270481427-Response-Times)는
주 단위 검토와 지연 시 최대 3주를 안내하지만 2023년 작성 문서이므로 현재 승인 일정의 보장으로 쓰지 않는다.

## 4. 준비 작업과 완료 기준

아래 항목은 신청 준비용 작업 목록이다. 이번 문서 작성이 외부 신청 제출·광고 게재·전적 개발까지 수행했다는 뜻은 아니다.

- [ ] 기존 Riot 제품 등록, 현재 상태, 키 보유 여부 확인
- [ ] 현재 위키와 무료 열람·광고 모델을 설명하는 신청 문안 확정
- [ ] 실제 공개 사이트에서 탐색 → 문서 → Me 선택, 로그인 → 편집 → 검토 흐름 확인
- [ ] 이용약관·개인정보처리방침·문의 경로·Riot 비공식 고지의 실제 노출과 내용 확인
- [ ] 카테고리 대표 이미지 등 사용 권리가 미확인된 에셋 검토 — [HANDOFF 5.4](./HANDOFF.md#54-외부-의존성)
- [ ] 필요 시 심사용 시연 영상·스크린샷 준비
- [ ] 포털이 요구하는 사이트 소유권 인증 완료
- [ ] 신청 제출 후 제품 ID·신청일·신청 범위 기록
- [ ] Riot의 보완 요청 처리 및 `Approved` / `Acknowledged` 등 실제 결과 기록
- [ ] 수익화 가능 범위 확인 후 광고 도입 범위·일정 결정

### 신청 설명 초안

> 깨남.COM은 한국어 사용자를 위한 리그 오브 레전드 상대법 위키입니다.
> 사용자는 포지션별로 상대 챔피언을 탐색하고, 보편적인 공통 상대법과 내 챔피언 전용 상대법을 함께 읽습니다.
> 로그인한 사용자는 공략을 공동 편집하며, 기존 내용을 지우거나 고치는 편집은 운영자 검토를 거칩니다.
> 챔피언·스킬 정보와 이미지는 Riot Data Dragon을 사용하고, 공략 본문은 사용자가 작성합니다.
> 현재 전적 검색 API는 사용하지 않습니다. 무료 열람을 유지하면서 사이트 광고로 운영비를 충당하는 모델을 검토하고 있으며,
> 현재 제품의 등록·심사와 해당 수익화 모델의 적용 조건 확인을 요청합니다.
> 전적 검색은 향후 확장 계획이며, 도입 전에 제품 정보를 갱신하고 필요한 API 권한을 신청할 예정입니다.

실제 제출 전에 배포된 기능과 일치하는지 검토한다. 이 초안은 제출되지 않았다.

### 후속 기록란

| 항목 | 값 |
| --- | --- |
| 제품 ID / 포털 제품 주소 | 미확인 |
| 등록·신청 유형 | 미확인 |
| 제출일 / 제출 범위 | 미확인 |
| 소유권 인증 상태 | 미확인 |
| 제품 상태 / 확인일 | 미확인 |
| 수익화에 대한 Riot 답변·조건 | 미확인 |
| Production 키 발급 여부·허용 범위 | 미확인 |
| 보완 요청 / 다음 작업 | 포털의 현재 등록 상태부터 확인 |

API 키, 인증 비밀값, 계정 비밀번호와 개인정보는 이 문서나 저장소에 기록하지 않는다.

## 5. 후속 후보: 전적 기능

아래는 대화에서 제안한 범위이며 구현 확정 사항이 아니다. 착수할 때 PRD와 디자인 기준에 반영한다.

- 한국 서버, Riot ID 검색, 최근 20경기, 현재 티어부터 검토한다.
- 승패·챔피언·KDA를 보여 주고, 해당 경기의 상대법 문서와 Me 선택으로 연결하는 흐름을 검토한다.
  연결 주소는 구현 시점의 문서 라우트와 유효성 규칙을 따른다.
- Riot 서버 호출은 서버에서 수행하고 키를 보호한다. 캐시, 중복 요청 제어, 갱신 제한,
  429 응답의 `Retry-After` 준수, 없는 계정·전적·서버 장애 처리가 필요하다.
- 최근 경기 집계와 시즌 전체 통계를 명확히 구분한다. 대규모 시즌 통계·분석은 별도 범위로 둔다.

Riot ID와 호출 제한 근거: [LoL 계정 조회 안내](https://developer.riotgames.com/docs/lol#summoner-names-to-riot-ids),
[응답 코드 안내](https://developer.riotgames.com/docs/portal#response-codes).

| 후보 범위 | 난이도·개발 추정 |
| --- | --- |
| 검색 + 최근 20경기 기본 표시 | 중간, 약 3~7일 |
| 티어·경기 상세·캐시·오류 처리와 공개 운영 검증 | 중상, 약 2~4주 |
| 시즌별 분석·대규모 통계·많은 동시 사용자 대응 | 높음, 수개월 이상 |

기간은 현재 코드를 아는 숙련 개발자 1명의 집중 작업을 가정한 대화상 추정이다.
공식 일정이나 납기 약속이 아니며, Riot 승인 대기 시간은 별도다.
